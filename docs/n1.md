# 斐讯 N1（Phicomm N1 / Amlogic S905D）软件包说明

本文档记录本仓库（25.12.x 第三方 apk 存储）里与 N1 相关的通道、包来源和已知缺口。

## 1. N1 用哪条通道

| 构建方式 | 固件架构 | 取包通道 |
| --- | --- | --- |
| 源码编译（fanchmwrt `target/linux/amlogic` 的 `mesongx`，`CPU_TYPE:=cortex-a53`） | `aarch64_cortex-a53` | `run/arm64-a53/` |
| ImageBuilder（`immortalwrt/imagebuilder:armsr-armv8`，AutoBuildImmortalWrt 的 `n1/build25.sh`） | `aarch64_generic` | `run/arm64/` |

两条通道的 apk 不能互换：`aarch64_generic` 的二进制在 `cortex-a53` 目标上无法保证可用，反之亦然。

## 2. 晶晨宝盒 luci-app-amlogic（本次新增）

N1 把系统装进 eMMC、在线升级固件/内核、备份恢复、快照，GUI 入口只有晶晨宝盒。此前本仓库没有它的 apk 版本，N1 的 25.12 构建只能跳过（见 `AutoBuildImmortalWrt/n1/build25.sh` 的旧注释），对应的现象就是「N1 无法刷入 eMMC」。

| 项目 | 值 |
| --- | --- |
| 收录通道 | `run/arm64/amlogic/`、`run/arm64-a53/amlogic/` |
| 上游 | ophub/luci-app-amlogic，release tag `26.10.2002-js` |
| 包版本 | `luci-app-amlogic-26.10.2002-r2.apk`（`r2` = JS LuCI / main 分支） |
| 国际化 | `luci-i18n-amlogic-zh-cn-0.apk`、`luci-i18n-amlogic-ru-0.apk` |
| 包架构 | `LUCI_PKGARCH:=all`，依赖声明 `@(aarch64||arm)` → 故 **不收录到 `run/x86`** |
| 固件版本适配 | 25.12 默认 JS LuCI 用 `r2`；LuCI-Lua 系统（24.10）用同 tag 的 `r1`/`-26.10.2002-r1.apk` |

### 2.1 运行依赖（固件必须能提供，否则装不上）

来自上游 `Makefile` 的 `LUCI_DEPENDS`：

```
luci-base rpcd rpcd-mod-ucode bash blkid block-mount curl
dosfstools e2fsprogs fdisk jq losetup lsblk parted perl pv uuidgen
```

- ImageBuilder 路径下这些包大多能由 feed 自动解析，但 `bash`、`jq`、`pv`、`uuidgen`、`rpcd-mod-ucode` 常被裁掉，建议在 `PACKAGES` 里显式列出。
- 源码编译路径下 `target/linux/amlogic` 的 `DEFAULT_PACKAGES` 只带 `e2fsprogs mkf2fs block-mount resize2fs partx-utils losetup htop`（`mesongx` 另加 `ethtool parted`），其余要靠 `.config` 打开。

## 3. openwrt-daede 通道升级（arm64-a53）

`run/arm64-a53/openwrt-daede/` 由 2026.06.14 升级到 2026.10.18（上游 `kenzok8/openwrt-daede` tag `v2026.10.18-ae2bf72` 的 `aarch64_cortex-a53` 资产）：

| 文件 | 说明 |
| --- | --- |
| `dae-2026.10.18-r1.apk` | dae 主程序，cortex-a53 构建 |
| `daed-2026.10.18-r1.apk` | daed 主程序，cortex-a53 构建 |
| `luci-app-daede-1.15-r9.apk` | LuCI 界面（arch all） |
| `vmlinux-btf-6.12.103-r1.apk` | BTF 数据，仅在内核未开 `CONFIG_DEBUG_INFO_BTF` 时需要 |

`vmlinux-btf` 的 6.12.x 版本必须与固件实际内核一致；N1 若用别的 6.12.y，请用对应版本或直接让内核打开 BTF。

## 4. 已知缺口（未修，不要当成已完成）

- **ssrp 已升到 a53 可得的最新，但仍未与 arm64 齐平**：`run/arm64-a53/ssrp/` 现为 `luci-app-ssr-plus-196-r19` + `naiveproxy-150.0.7871.63.1-r1`（来自 `fw876/helloworld` v196.19，sha256 与上游 digest 一致）。i18n 仍是 `26.180.61284~d5de283`（配对 r2 的构建）：`luci.mk` 的 `LuciTranslation` 写的是 `DEPENDS:=$(PKG_NAME)`（不锁版本），所以可以并存安装，代价是新文案回落到英文。`run/arm64` 的 `naiveproxy 154.0.8037.49-r4` / i18n `26.280.28888` 没有公开的 a53 构建，要对齐只能自建 SDK CI（可参考 `zlwu/helloworld-dist` 按目标架构分支出包的做法）。
- **未脱机验证**：所有包只做了「上游 sha256 一致 + apk v3 魔数 `ADBd` + 文件名/架构」校验，没有在 N1 真机上执行 `apk add`。
- **x86 通道不收录 amlogic**：上游依赖写死 `@(aarch64||arm)`。
